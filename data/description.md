## 📌 ГРУППА 5: Агрегированная активность (колонки 21–90)

Самая большая группа. Все колонки имеют одинаковую структуру:

**`{тип_действия}_{временное_окно}`**

### Что означают типы действий:

| Тип действия | Что это за действие |
| :--- | :--- |
| `item_views` | Просмотры конкретного объявления |
| `item_favorites` | Добавление этого объявления в избранное |
| `detail_expands` | Раскрытие деталей объявления |
| `photo_swipes` | Пролистывание фото в объявлении |
| `seller_page_views` | Просмотры страницы продавца |
| `search_views` | Просмотры результатов поиска |
| `query_refinements` | Уточнения поискового запроса |
| `similar_item_clicks` | Клики по похожим объявлениям |
| `saved_search_matches` | Совпадения с сохраненными поисками |
| `user_contacts` | Контакты с пользователем |
| `chat_opens` | Открытия чата |
| `call_clicks` | Клики по кнопке звонка |

### Временные окна:
`1d`, `3d`, `7d`, `14d`, `30d`, `90d`.

**Пример**: `photo_swipes_14d` 

---

## 📌 ГРУППА 6: История предыдущих обращений (колонки 91–108)

| Колонка | Что означает |
| :--- | :--- |
| `leadgen_prev_assigned_{окно}` | Сколько обращений было назначено пользователю за окно |
| `leadgen_prev_answered_{окно}` | Сколько из них было отвечено |
| `leadgen_prev_positive_{окно}` | Сколько из них привели к успеху |

**Пример**: `leadgen_prev_positive_30d` = сколько успешных обращений было у этого пользователя за последние 30 дней.

---

## 📌 ГРУППА 7: Активность по авто (колонки 109–114)

| Колонка | Что означает |
| :--- | :--- |
| `active_days_auto_{окно}` | Сколько дней пользователь был активен в разделе авто за окно (смотрел авто, искал и т.д.) |

**Пример**: `active_days_auto_7d` = пользователь был активен в авто-разделе 3 дня из последних 7.

---

## 📌 ГРУППА 8: Целевая переменная (последняя колонка) **(Только в train.csv)**

| Колонка | Что означает |
| :--- | :--- |
| `target` |  1 = успешное целевое действие в течение 5 дней после назначения, 0 = нет |

---

## Визуальная схема

```
Строка в train.csv = ОДНО ОБРАЩЕНИЕ
│
├── Кто? (user_id, регион, стаж, цена авто...)
├── Когда? (assignment_ts, час, день недели...)
├── Контекст? (источник, канал, колл-центр...)
├── Что делал до звонка?
│   ├── Смотрел это авто (item_views_1d, 3d, 7d...)
│   ├── Добавлял в избранное (item_favorites_1d...)
│   ├── Листал фото (photo_swipes_1d...)
│   ├── Искал похожее (search_views...)
│   └── Контактировал (chat_opens, call_clicks...)
├── Что было с предыдущими обращениями?
│   ├── Сколько было назначено (leadgen_prev_assigned...)
│   ├── Сколько ответили (leadgen_prev_answered...)
│   └── Сколько успешных (leadgen_prev_positive...)
└── РЕЗУЛЬТАТ → target = 1 (успех) или 0 (нет)
```

# 📊 Файл `events.csv` — сырые события пользователей

В отличие от `train.csv` и `test.csv`, где каждая строка — это **одно обращение (лид)**, в `events.csv` каждая строка — это **одно действие пользователя** на платформе.

---

## 📌 ГРУППА 1: Идентификаторы и время

| Колонка | Что означает | Пример |
| :--- | :--- | :--- |
| `lead_id` | ID обращения, к которому относится событие. Связывает событие с конкретным лидом | `lead_789` |
| `user_id` | ID пользователя, который совершил действие | `user_123` |
| `event_ts` | Точное время, когда произошло событие | `2026-08-10 10:15:00` |

**Важно:** Один `lead_id` может иметь **много событий** в `events.csv`. Например, до звонка пользователь мог 5 раз посмотреть объявление, 2 раза добавить в избранное, а затем позвонить — и все это будет в `events.csv` с одним и тем же `lead_id`.

---

## 📌 ГРУППА 2: Тип события

| Колонка | Что означает | Примеры |
| :--- | :--- | :--- |
| `event_type` | Тип действия, которое совершил пользователь | `item_view`, `favorite_add`, `phone_click`, `chat_open`, `search_view` и т.д. |

Это **категориальная** переменная. 

---

## 📌 ГРУППА 3: Дополнительные параметры события

| Колонка | Что означает | Пример |
| :--- | :--- | :--- |
| `item_price_log` | Логарифм цены товара, с которым связано событие | `14.7` |
| `src_slot` | Позиция/слот, где было показано объявление (в выдаче, на странице и т.д.) | `1`, `2`, `3` |
| `ctx_seq` | Порядковый номер события в рамках контекста (например, последовательность действий пользователя) | `0`, `1`, `2` |

---

## 🧠 Как эти данные превращаются в признаки из `train.csv`

### Схема преобразования:

```
events.csv (сырые события)
    │
    ├── Фильтруем по времени: event_ts < assignment_ts
    │
    ├── Группируем по lead_id и event_type
    │
    ├── Считаем количество событий каждого типа
    │   за разные временные окна (1d, 3d, 7d...)
    │
    └── Получаем признаки как в ГРУППЕ 5:
        item_views_1d, item_views_3d, ...
        favorites_1d, favorites_3d, ...
        chat_opens_1d, chat_opens_3d, ...
        call_clicks_1d, call_clicks_3d, ...
```


---


## Визуальная схема для events.csv

```
Строка в events.csv = ОДНО ДЕЙСТВИЕ ПОЛЬЗОВАТЕЛЯ
│
├── Кто? (user_id)
├── К какому обращению относится? (lead_id)
├── Когда произошло? (event_ts)
├── Что сделал? (event_type)
│   ├── item_view — посмотрел объявление
│   ├── favorite_add — добавил в избранное
│   ├── phone_click — кликнул по кнопке звонка
│   └── ... (другие типы)
└── Детали действия (item_price_log, src_slot, ctx_seq)
```
